# 需求与验收

## 目标与使用者

面向进行程序设计实践的两位成员，提供一个足够小、可直接运行、有明确模块边界和测试的项目，用于体验 GitHub 完整协作流程。

基础版本是可运行成品。参与者通过[练习任务卡](exercises.md)扩展功能，而不是先修复一个故意损坏的项目。

## 基础需求

| 编号 | 需求 | 验收行为 |
| --- | --- | --- |
| F01 | 创建任务 | 必填标题，可选负责人，生成正整数 ID，状态默认为 `todo` |
| F02 | 查看任务列表 | 无筛选时显示全部；支持状态、负责人精确匹配及二者组合；按 ID 升序 |
| F03 | 查看单条任务 | 按 ID 显示全部四个字段；不存在时明确报错 |
| F04 | 修改任务 | 至少修改标题、负责人、状态中的一项，其他字段保持原值 |
| F05 | 删除任务 | 立即删除指定 ID；重复删除报任务不存在 |
| F06 | 数据持久化 | 命令退出后数据保留，下次使用同一数据库可继续操作 |
| F07 | 可解释的错误 | 参数错误退出 2，业务及存储错误退出 1；预期错误不显示 Python 调用栈 |
| C01 | 双人协作 | 每项需求有开发人、评审人、Issue、分支、PR、测试和文档 |
| C02 | 自动验证 | PR、推送到 `main`、手动触发均有 CI 配置 |
| C03 | 用户掌握 Git | 所有 Git 命令由用户手动执行，助手仅提供说明 |

## 数据规则

- 标题去除首尾空白后必须非空，内部空格及中文原样保存。
- 负责人为可选文本，去除首尾空白，空值代表未分配；不是 GitHub 账号绑定。
- 新任务为 `todo`；更新可在 `todo`、`doing`、`done` 间任意切换，包括保持原状态。
- ID 使用 SQLite 自增主键，删除后不复用；命令接受 1 到 `9223372036854775807` 的整数。
- 同时提供状态和负责人时取交集；负责人区分大小写。空负责人筛选属于业务错误。
- 没有匹配任务时，文本模式输出 `暂无任务。`，`--json` 模式输出 `[]`，均成功退出。
- `stats` 统计当前数据库的全部任务，不接受筛选参数。固定输出 `total`、`todo`、`doing`、`done` 四行，空库或缺失状态显示 0，总数等于三种状态数量之和；统计不修改已有任务数据。

## 项目边界

本项目围绕代码协作展开，每人维护本地任务数据。基础版本不提供网络服务、账号权限、跨机器数据同步、打包发布或数据库迁移工具。

扩展练习 `list --json` 已实现：输出包含 `id`、`title`、`assignee`、`status` 的 JSON 数组，保留中文、整数 ID 和未分配时的 `null`，沿用筛选、排序及错误约定。`stats` 也已实现，沿用全局数据库路径和错误处理约定，无需修改任务模型或数据库表结构；实现要求与验收进度见[任务卡](exercises.md)。

## 完成标准

1. 在仓库根目录仅使用 Python 3.11+ 即可运行，不需要第三方包。
2. [README](../README.md) 的快速开始可在空数据库上完整执行。
3. `python -m unittest discover -s tests -v` 全部通过，测试不改动个人数据。
4. 需求、架构图、接口、代码、测试行为相互一致，文档相对链接有效。
5. 两位参与者能按指南进行功能开发、交叉评审及独立分支冲突演练。
6. 推送后在 GitHub 检查四项 CI 组合；本地测试通过不等同于线上 CI 已通过。
